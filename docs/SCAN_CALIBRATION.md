# 扫描速度校准验收

## 范围

本地规则助手，按练习结果选择下一组扫描速度，完成后提出建议，由用户决定是否接受。没有修改 EEG 识别阈值、模型、服务器协议或候选词排序。

策略版本：`scan-speed-practice-v1`。每组重复同样的目标次序，降低不同目标位置造成的比较偏差；仍存在练习顺序、学习和短样本的影响，真实效果需要进一步比较。

## 自动检查

在项目目录执行，使用 JDK 21：

```sh
bash ./gradlew :app:testDebugUnitTest :app:assembleDebug
bash ./gradlew :app:lintDebug
```

`ScanCalibrationTest` 覆盖正常完成、组间调整、正确率优先、无可靠结果、两轮超时、第二轮选择、输入模式隔离、暂停恢复、阻塞暂停、速度边界、确定性回放及保存选项门槛。

## Pad 手动验收

使用横屏 Pad 模拟器（例如 Pixel Tablet，2560 × 1600，320 dpi），不用手机尺寸替代。

1. 记录原扫描速度，打开“实时沟通 → 校准速度”，进入模拟练习。
2. 等待指定目标高亮，用“确认当前项”或悬浮球咬牙确认。完成 12 题，核对进度、三组速度和正确次数；检查组内速度不改变。
3. 另一次练习故意选错或等待两轮，确认记录中有选错或未确认，下一组减速；若每组均不足 3 次正确，不应提供保存选项。
4. 中途暂停、切后台再返回，确认不会自动作答或恢复；选择继续时重做当前题，保留已完成记录。
5. 结果页先选择放弃，确认原速度不变；再完成练习并接受建议，重启应用确认设置保留。首页和娱乐使用同一个全局设置。
6. 应用设置页通过自动轮转进入校准，确认选中的设置卡片会滚动到可见区域。
7. 接入真实耳机并在设置中启用控制，进入耳机练习；悬浮球咬牙不应记录作答，真实动作可以作答。断流应暂停并禁用继续，重新连接且启用控制后才能继续。
8. 用同一组目标比较原速度与推荐速度下的正确率、完成耗时和主观舒适程度，再决定是否长期采用。

## 本地记录

每次有作答的练习对应一个 UUID 命名的 JSON。`outcome` 为 `pending`、`accepted`、`discarded` 或 `retry`。`mode` 区分 `SIMULATION` 与 `HEADSET`；中断次数单独保存。文件通过原子写入替换，并串行保存，避免旧结果覆盖用户最终选择。
